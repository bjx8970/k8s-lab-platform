# Job 安全重试

当前结论（2026-09-02）：重试接口已纳入最终完整回归，canonical/default 各运行一次，均 152/152 通过，分别耗时 8.807 秒和 9.121 秒，失败/错误/跳过均为 0。D 独立 retry 专项此前 13/13、4.666 秒通过，也全部纳入两次全套。上一轮“无 retry 接口”的结论仅属于历史基线，不再作为本轮支持范围描述。

## 请求与权限

`POST /api/k8s/tasks/<task_id>/retry` 使用已登录 Session，遵守 HTTP Origin 白名单，并携带从 `/api/csrf-token` 获得的 `X-CSRFToken`。请求引用源任务；操作类型、集群及其资源指纹来自服务端私有描述，客户端不能通过请求体指定其他操作、资源或执行者。

管理员可重试获准的任务，教师可重试自己或自己所属环境的任务；无关教师与学生返回 403。教师重试管理员为其环境创建的任务时，新任务的创建者/执行者为当前教师，所属教师字段保持正确，不能沿用原管理员权限。新任务的列表、详情、日志和 `task_update` 继续遵守任务授权规则。

成功返回 `202 {"task_id": "新任务ID", "retry_of": "源任务ID"}`。服务先校验 TASK_RETRY 权限：管理员查询不存在的源任务返回 404，其他角色可能先因无权访问该源返回 403；状态、描述或重试占用冲突返回 409；权限拒绝返回 403。缺少或无效 CSRF 返回 400，未登录返回 401，禁止 Origin 返回 403。未知入队异常返回安全的 HTTP 500，而不是业务参数错误 400；不得把原始异常中的密码或私钥发给浏览器。

## 可以安全重试的范围

| 源任务 | 状态/阶段 | 行为 |
| --- | --- | --- |
| deploy | error 或 cancelled，且有服务端描述 | 创建新的 deploy 任务 |
| delete | error 或 cancelled，且有服务端描述 | 创建新的 delete 任务 |
| create 后自动部署 | VM 创建已成功，后续 auto-deploy 失败 | 仅创建 deploy 重试任务，不再创建或复制 VM |
| create 创建阶段失败 | VM 创建未确认完成 | 返回 409，不自动重放创建流程 |
| 任意任务 | running、completed，或已经有一个直接重试子任务 | 返回 409，不重复入队 |
| 历史任务 | 仍有任务记录但没有服务端可执行描述 | 返回 409，不采信客户端补传的描述 |

同一源任务只允许一个直接重试子任务。创建失败可能已经留下部分 VM 或网络资源，必须先检查实际资源和任务日志，按相应补偿/清理流程处理；不能把 create 请求当作可重复复制 VM 的重放命令。

如果新子任务入队失败，必须释放源任务的重试占用，不留下虚假的 running/queued/pending 子任务，并仅记录失败审计，不能提前记录重试成功。队列恢复后，同一源任务仍可重新发起一次有效重试。

当前授权在提交时校验，worker 出队时再次加载操作者及集群。若操作者已被禁用，或集群的提供器/VM 身份相对服务端记录发生变化，拒绝继续执行，不触发部署或提供器操作。支持的是明确记录的安全重试，不代表所有失败任务都可重放。

## 进程内生命周期

Job 继续使用既有进程内队列，历史记录按现有机制约保留 30 分钟；重试元数据与源任务具有相同生命周期。本 Issue 不引入持久 Job 或跨进程恢复，不保证进程重启后还能查询或恢复历史任务。源任务已不在内存时，管理员得到 404，其他角色可能先得到授权拒绝 403；通过授权且任务记录尚在但缺少安全执行描述时返回 409。上述保留时间也不是持久化承诺。

## 审计与秘密边界

`job.retry` 成功审计应能关联当前操作者、源任务和真实新子任务；拒绝/失败审计应包含操作者和源任务，不要求失败一定产生可关联的子任务。入队失败可能回滚已创建的子任务，不能伪造不存在的子 ID，也不能记录成功。默认 root 日志级别 WARNING 不能过滤成功安全审计。

HTTP 响应、任务详情/列表、Socket 更新和审计中不得出现私钥、密码、密文或服务端执行描述/指纹。后台描述只供服务执行使用，不能让前端编辑后回传重放。

## 验收及发布

独立用例位于 `tests/test_issue1_retry_acceptance.py`，使用真实 Flask/SocketIO、manager/service、临时 SQLite 用户和集群，捕获队列任务并以模拟操作制造源任务失败。不会直接伪造服务端重试描述，不会连接真实基础设施。

本轮已单次执行 D 组 13 条专项，全部通过；覆盖入队异常的安全 500、失败审计无 success、释放占位、无运行中残留子任务，以及队列恢复后同源重试 202。真实凭据文件、网络连接、非 SQLite 引擎/真实数据库连接护栏触发均为 0，创建 13 个临时 SQLite 引擎；结束时仅主线程和既有 4 个空闲队列 worker，无 SSH 清理线程。未直接构造可信重试描述；三个私有容器逐用例清空隔离。

最终 canonical 与 default 两种发现各执行一次，均为 152/152，预期失败/意外成功也均为 0；外层计时分别为 8.806918 秒、9.120765 秒。每次真实凭据文件、真实网络、非 SQLite 引擎及真实数据库连接护栏触发均为 0，各创建 24 个测试 SQLite 引擎。发现后及执行结束均只有主线程与既有 4 个空闲队列 worker，新增遗留线程为 0，无 SSH 清理线程。

两种发现均无重复收集用例；default 仍有部分 helper 的带/不带 `tests.` 前缀双名称导入，未改变用例数、结果和隔离边界，推荐 canonical。两次实际 url_map 均为 109 条路由，含唯一 POST/OPTIONS `/api/k8s/tasks/<task_id>/retry`。此前 101/101 是上一轮历史；本轮新增 HTTP retry 9、Job retry 29、D retry 13，共增加 51 项。

Issue 原六项安全代码验收均通过：原始提供器写权限、Job/WebSSH 所有权、秘密输出边界、认证/CSRF/状态码与握手、Origin 白名单、权限矩阵及成功/拒绝/失败审计。结论来自真实接口与隔离自动化，不代表执行了真实基础设施操作。逐项证据、完整命令、历史与当前结果见 [Issue #1 验收记录](issue-1-acceptance.md)。
