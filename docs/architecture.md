# v1 架构与产品边界

状态：目标设计，尚未实现。更新日期：2026-10-22。本文件是正式设计规范，不是旧重构计划、实施排期或运行验证记录。

入口：[README](../readme.md)。专题：[插件](plugin-contract.md)、[模板与资源](template-resource-contract.md)、[执行持久化](execution-persistence-contract.md)、[身份安全](identity-security-contract.md)。

## 1. 平台目标

管理员编写并发布实验环境模板，教师选择模板、填写允许的参数，平台按模板构造请求并调用插件。模板完成后，平台根据结果生成实验资源及其动作绑定。教师将环境分配给同一课程内的组和/或学生，学生使用获授权的资源与访问入口。

新增外部资源类型，应通过新增插件和使用该插件的模板实现，不要求核心增加供应商专用字段、动作分支或数据表。核心不理解 PVE、OpenWrt、SSH 的具体业务含义，也不将所有插件内部对象纳管为资产。

首版先验证通用平台功能、插件接入规范和 SSH 命令执行插件。SSH 插件维护主机清单并执行管理员模板里的命令；清单中的主机不必成为实验产出，也不默认是学生登录目标。不以完整 PVE/OpenWrt/Kubernetes 支持作为首版前提。

## 2. 信任模型

- 管理员和安装在可信目录中的插件代码是受信任主体。
- Manifest 是插件技术能力的权威来源。平台检查接口兼容、动作是否存在、参数是否符合 Schema，不建立第二份供应商能力白名单或危险命令审查器。
- 管理员可以发布包含 SSH 命令正文的模板。声明式模板不执行本地任意 Python，不等于禁止管理员通过 SSH 动作执行远端 Shell。
- 教师、学生不能绕过模板自由调用插件。参数、动作、目标、角色和环境归属必须由后端校验。
- 进程内 Python 插件不是安全沙箱。禁止直接 SQL/DDL 是架构契约，不代表恶意插件被技术隔离；平台不从数据库加载可执行代码。
- 可信插件仍可能出错，可信管理员不能消除网络分区、进程崩溃或重复投递，因此持久化、未知结果和恢复协议仍为必要条件。

## 3. 角色与职责

| 角色 | 允许 | 不允许 |
| --- | --- | --- |
| 管理员 | 用户、教师配额、插件配置、模板发布、全部环境和资源、凭据与终端管理 | 在未确认外部事实时把未知结果伪装成成功或已删除 |
| 教师 | 自己的课程、小组、成员；创建学生账号；通过模板创建、分配和管理自己环境；查看和接管自己环境的学生终端 | 创建模板、管理插件配置、直接构造插件调用、访问其他教师环境 |
| 学生 | 本人允许字段；授权环境/资源状态、凭据、WebSSH、模板开放的启停重启等动作 | 创建/删除环境、分配环境、管理课程/模板/插件、访问未分配资源 |

模板的角色列表只能进一步限制业务授权，不能给学生提升为管理员或授予环境删除权限。创建教师对学生账号的唯一管理权按身份规范处理，不等于对学生其他课程资源的管理权。

## 4. 逻辑架构与调用方向

```text
用户
  → 环境/资源的模板动作入口
  → 授权、参数、配额及冲突校验
  → Job / Step / Operation
  → Plugin Runtime
  → 插件声明动作
  → 外部系统

插件 → Runtime Storage → 平台通用私有存储
插件 → Runtime Secrets → 当前调用获准的凭据
插件 → Runtime Events → Operation 进度、检查点、已知外部引用

插件返回执行结果
  → 平台保存成功输出或失败/未知事实
  → 平台按模板生成实验资源和动作绑定
```

不存在教师/学生直通插件的业务 API，也不存在插件主动调用的 Resource Registration API。资源从模板和执行结果生成，内部存储、资源归属和授权均由平台服务维护。

插件配置管理、模板发布前的只读选项查询、运行恢复查询及交互会话帧属于各自受控入口，不可借此提供用户自由选择插件动作的通道。

## 5. 领域对象

| 对象 | 语义 |
| --- | --- |
| Plugin | 从目录加载的实现和 Manifest，定义动作与协议特性 |
| PluginInstance | 一个配置命名空间及身份，关联某插件，不要求对应一个物理设备 |
| PluginStorage | 插件私有 JSON 内容，按实例隔离，带不可变历史版本 |
| TemplateVersion | 管理员发布的参数、创建步骤、资源、动作、cleanup、配额与访问定义 |
| Environment | 某教师在一门课程内从固定模板版本实例化的实验环境 |
| ExperimentResource | 平台按模板生成的实验产出，具有专有数据及动作绑定 |
| EnvironmentAssignment | 环境对本课程学生或小组的授权路径，可同时存在多条 |
| Job | 一次创建、动作、清理、恢复等用户或系统请求 |
| Step | 固定流程展开后的步骤实例 |
| Operation | 一次准备和派发的插件调用事实；可能未知，不等于 Job |
| InteractiveSession | 独立于普通 JSON 返回值的双向连接及其平台元数据 |
| ConflictProtection | 对未决执行持久保留的冲突范围，不随 worker 租约自动消失 |
| QuotaReservation | 教师配额预留、占用、未知隔离与释放记录 |
| SecretVersion | 平台保存的加密凭据版本，不进入普通快照或日志 |

## 6. 模板、资源和外部对象的区别

- 一次模板执行可以产生零个、一个或多个实验资源。
- 一个实验资源可以表示 VM，也可以表示逻辑集群或多个外部对象的组合。
- SSH 执行所用管理主机可以只存在于插件 Storage；核心不强制建立资产 Binding、独占分配或主机容量模型。
- 平台资源没有统一的 VMID/IP/external_key 必填字段。外部引用是插件/模板解释的不透明数据，平台保存来源和稳定逻辑产出键。
- 已知外部引用不等于成功输出，成功输出不等于环境就绪。失败现场必须可追溯，不能因为资源尚未正式生成就丢失外部引用。
- 创建失败默认保留现场。平台不推断逆操作或自动回滚；用户显式触发模板 cleanup。
- 资源和环境动作都是模板定义的流程；“启动全部”不能由核心猜测哪些子资源需要启动。

## 7. 物理部署

v1 为单个控制平面进程加 PostgreSQL：

```text
Control Plane Process
  HTTP / 实时连接
  身份、授权与审计
  模板、环境与实验资源服务
  有界 Job 执行线程池
  恢复/周期扫描
  交互会话管理
  插件注册表与运行时

PostgreSQL
  业务对象、插件私有数据及版本
  Job / Step / Operation / 检查点
  冲突保护、配额、凭据、会话元数据、审计
```

- 不拆分 Web/Worker/Monitor 进程，不要求 Redis 或专用消息中间件。
- 后台组件显式启动、停止；模块导入不得读库、连接外部系统或启动线程。
- 只允许一个有效协调实例；重复启动、Web 多 worker 或开发重载配置必须被拒绝或通过持久租约防止重复协调。
- PostgreSQL 保存恢复事实。通知和内存事件只用于加速，周期全量扫描兜底。
- 会话元数据可持久化，但这不代表 TCP/SSH 连接或 PTY 能跨进程重启恢复。
- 插件目录扫描只执行受信任代码。v1 无热更新、在线安装、多版本共存；代码变化后的未完成调用必须检查兼容引用，不静默重新解释。

## 8. 数据与技术边界

- 目标持久化数据库仅 PostgreSQL，Schema 变更使用版本化 Alembic migration，不使用启动时 create_all + 吞异常 ALTER 维护新结构。
- 通用字段和外键由核心定义；插件私有 JSON 由插件解释，核心不动态建立插件/资源专用表。
- 所有持久时间使用带时区时间；配额和计数单位明确。JSON 数值、列表和展开数量必须有界。
- 环境、资源、执行事实采用保留历史的删除/归档策略；不能级联抹掉故障引用和审计。具体 DDL、索引及保留期尚待实现设计，不冒充已经落库。
- UI 必须能按模板生成参数表单和动作入口。前端框架及是否替换当前 Jinja 的具体技术选择尚未最终确定，本文不指定 SPA 技术栈。

## 9. 首版范围与明确非目标

首版必须覆盖：插件启动加载、通用存储、SSH 操作、多步模板、有界 for_each、平台资源及动作绑定、课程分配、教师配额、PostgreSQL 执行事实、WebSSH/接管、审计和失败保留现场。

后续而非首版：

- 插件 Web 安装/更新、热加载及多版本并存。
- 模板之间相互引用；不得在首版中伪造一个已支持的 template_ref 字段。
- 平台学生与环境 OS 账号一一绑定。
- 私有 SSH CA、证书签发及 AuthorizedPrincipalsCommand。
- 通用基础设施 CMDB、主机独占调度和供应商专用资产台账。
- 多控制平面实例、微服务或独立 Worker/Monitor 部署。
- 自动审查可信管理员命令、固定的供应商操作白名单。
- 无条件逆序补偿、对未知变更自动重发。
- 旧系统兼容适配和旧数据自动迁移。

## 10. 验收原则

接口、状态机和原子性必须用 Fake 插件、数据库事务及故障注入测试验证；真实 SSH 验收不能代替并发/恢复测试。现有旧测试不证明目标契约已实现。

最低闭环：管理员配置 SSH 插件私有数据并发布模板；教师实例化、配额原子预占；平台按步骤调用并保存结果，生成声明的资源与动作；教师分配；学生按模板使用资源和访问入口；教师可旁观接管；失败保留事实，显式 cleanup 确认后释放占用。清单、管理连接和学生终端入口不得被自动混同。
